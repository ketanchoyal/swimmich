# Task: i18n

**Objectif** : Compléter l'internationalisation d'ImmichSwiftUI. Actuellement le texte est en FR/EN hardcoded avec un catalogue `Localizable.xcstrings` partiel. Objectif : tous les textes UI externalisés, support de toutes les langues iOS, fallback automatique.

**Hypothèses** :
- `Localizable.xcstrings` existe dans le projet (format Xcode String Catalog).
- Le projet cible iOS 26 (support natif `.strings catalogs`).
- Les textes sont hardcodés dans les Views (labels, placeholders, messages d'erreur, titles, sheet headers).
- Les erreurs API sont retournées en anglais par le serveur Immich (messages techniques).
- `UserDefaults` pour le language selection `appLanguage`.
- Le Flutter a une feature toggle "Language" dans Settings — on peut s'y inspirer.
- `RootView.swift` expose `openProfile` environment value — sur cette même vue on peut mettre un language picker.

**Approche retenue** : A — migration systématique de tous les string literals en `String(localized:)` ou `Text("key", bundle: .module)` + catalogue `Localizable.xcstrings` complété + language picker dans Settings.
- **B (rejetée)** : nouveau i18n framework. iOS 26 support natif, inutile d'ajouter une lib.
- **C (rejetée)** : fichiers `.strings` traditionnels. Les String Catalogs (.xcstrings) sont le standard moderne Xcode.

## Étapes

1. **Audit des strings hardcodés** :
   - Scanner tous les ViewModels et Views pour string literals ("en ligne", non-localized).
   - Catégories : titles, labels, placeholders, error messages, sheet headers, button text, empty state messages, accessibility labels, time formats, formatting strings.
2. **Localizable.xcstrings** — Compléter :
   - Ajouter toutes les strings manquantes dans le catalogue.
   - Ajouter les traductions FR + EN pour chaque string.
   - Structurer par module : `auth.*`, `timeline.*`, `viewer.*`, `editor.*`, `albums.*`, `search.*`, `map.*`, `memories.*`, `people.*`, `tags.*`, `admin.*`, `upload.*`, `shared.*`, `trash.*`, `profile.*`, `settings.*`, `shared.*`.
3. **String localization passes** :
   - `LoginScreen` : labels email/password, "Sign in", error messages.
   - `TimelineView` : titles, empty states, pull-to-refresh, multi-select actions.
   - `PhotoViewer` : action sheet titles (favorite, delete, share, info, edit, open maps), labels.
   - `PhotoEditorView` : slider labels (brightness, contrast, exposure), action text (save, revert, share).
   - `AlbumsView` : "Create album", "Shared links", empty states.
   - `SearchView` : "Search...", "Smart", "Explore", placeholders, filters labels.
   - `MapView` : titles, empty states, zoom controls.
   - `MemoriesView` : "On this day", year labels, empty states.
   - `PeopleView` : titles, empty states, "Create person", error messages.
   - `TagsView` : "Create tag", empty states.
   - `AdminView` : titles, button labels, error messages.
   - `UploadView` : settings labels, error messages, progress text.
   - `SharedLinksView` : titles, action labels, empty states.
   - `TrashView` : "Restore all", "Empty trash", empty states.
   - `ProfileView` : settings section titles, button labels.
   - `Settings` : labels, section titles.
   - Error messages : `Localizable.xcstrings` entries pour les erreurs connues (network, auth, upload).
4. **Language picker** — NEW `Sources/Features/Settings/LanguageSettingsView.swift` :
   - Liste des langues supportées.
   - Valeur persistée dans `UserDefaults("appLanguage")`.
   - Relance l'app au changement (recreate the root).
5. **DateFormat hoisting** — Créer `AppDateFormat` singleton dans DesignSystem avec des `DateFormatter` réutilisés (pas de création par render).
6. **Tests** — `LocalizationTests` (vérifier que chaque écran a ses traductions).
7. **xcodegen + suite**.

## Acceptance Contract

### Approches candidates
**A (retenue)** : `.localized` / `Text("key")` + Localizable.xcstrings + language picker. Standard iOS moderne.
**B** : Framework tiers (SwiftGen, Lingo, etc.). Inutile sur iOS 26.
**C** : Fichiers `.strings` classiques. String Catalogs sont mieux.

### Approche retenue + rationale
**A**. Standard iOS 26 natif, pas de nouvelles deps, outils Xcode intégrés. Parité avec les bonnes pratiques Apple.
