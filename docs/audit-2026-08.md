# immich_swiftui — Consolidated Audit (2026-08-07)

Scope: research/documentation artifacts, runtime performance, and Apple-HIG / iOS 26 design.
Method: read-only. Every finding cites `file:line`. No code changed.

---

## 0. Executive summary

This is a **strongly governed** codebase for an Apple-like (not ported) Immich client. A real design system lives under `Sources/DesignSystem/` (tokens + components), state management uses modern `@Observable` everywhere (no `ObservableObject`/`@Published`), native iOS 26 patterns are preferred (`Form`/`List`/`ContentUnavailableView`/`.searchable`/`Tab(role: .search)`), and a disciplined acceptance-contract methodology drives feature delivery. The PhotoViewer is a first-class iOS 26 glass citizen, Reduce Motion is honored, and accessibility grouping/traits are present.

The issues below are **polish, consistency, and big-library performance** concerns — not architectural problems. Highest-leverage work: cache/hoist `DateFormatter`s, stop recomputing the timeline section pipeline in `body`, switch the explore grid to stable `ForEach` ids, route all UI copy through the catalog, and complete the deprecated-token migration.

### 1.2 Findings — staleness, drift, accuracy

#### R1 (HIGH) — Inline source comment misrepresents timeline perf
`TimelineView.swift:314-315` carries the comment *"Computed on every render — cheap (linear scan)"* on the body-computed property `timelineSections` (`TimelineView.swift:316-318`). The **scan** in `build` is linear, but `TimelineSectionBuilder.build(...)` constructs an `ISO8601DateFormatter` (`TimelineSectionBuilder.swift:52`) **and** a `DateFormatter` (`:57`) on every call, and `build` runs from `body`. On a large library this is two formatter allocations per render. The comment should be corrected so future work doesn't assume the pipeline is free. *(Correction: the original audit attributed a matching claim to `memory.md`. Re-verification found `memory.md` is silent on timeline perf cost — it never made that claim. The fix scope is the source comment only; `memory.md` needs no correction, though an additive perf note there would help — see the fix log appended 2026-08-07.)*

#### R2 (MEDIUM) — Orphaned `swiftui-apple-design/references/` (deliberate, but a navigation trap)
Git status shows the parent `SKILL.md` as deleted (` D .opencode/skills/swiftui-apple-design/SKILL.md`) while `references/{typography-color,layout-motion,components}.md` remain tracked and present. This was a **deliberate user decision** per `.zcode/plans/plan-sess_d14b21b4-*.md` (decision point 3: "delete only the old `SKILL.md`, leave `references/*` untouched"), not accidental drift. Either restore the SKILL.md (and re-symlink into `.zcode/skills/`) or formalize the removal with a one-line `README.md` in the folder so anyone navigating skills by folder isn't trapped. *(Resolved 2026-08-07: added `README.md` per the latter option.)*

#### R3 (MEDIUM) — Skills split across two trees; new skills untracked under `.opencode/skills/`
The 8 new skills (`ios-app-intents-system`, `ios-build-debug`, `swiftui-apple-docs-research`, `swiftui-architecture`, `swiftui-hig-design`, `swiftui-liquid-glass`, `swiftui-performance`, `swiftui-swiftdata-persistence`) live as real files with `SKILL.md` under `.opencode/skills/` but are **untracked** in git. `.zcode/skills/` is a parallel tree of **8 symlinks** → `.opencode/skills/<same-name>` (not separate copies, not empty — symlinked), and the whole `.zcode/` tree is untracked. The "two locations invite divergence" concern is real but lower-risk than it first appears because they're symlinked. **Fix:** git-track the canonical `.opencode/skills/` set so there's one version-controlled source of truth; leave `.zcode/` as a local working tree. *(Resolved 2026-08-07: `git add`ed the 8 new skills under `.opencode/skills/`.)*

#### R4 (MEDIUM) — No top-level `README.md`, no `docs/` dir until now
`.opencode/memory.md` is the de-facto onboarding doc for new contributors, but nothing says so. The pipeline, PRD, and design-system docs are scattered across the root and `.opencode/`. A short `README.md` (or this `docs/` index) pointing at the PRD, `PhotoVault-DesignSystem.md`, `memory.md`, and `AGENTS.pipeline.md` would lower the entry cost. *(Resolved 2026-08-07: added `docs/README.md` as the documentation index. A top-level project `README.md` is still absent — lower priority.)*

#### R5 (LOW) — Acceptance contracts mix shipped and backlog features
The 20 contracts in `.opencode/scratch/` (not 19 — original audit undercounted) include both **shipped** work (timeline redesign, onboarding revamps, search/map, design-system token sweep, trash, editor, app-lock, albums/share-link) and **partially-shipped** work (the i18n item in `v1.5-polish` is the open D1 finding). Without a status marker, a reader can mistake a backlog contract for completed acceptance. **None** of the contracts have YAML frontmatter — all begin with a plain `# Task:` markdown heading — so a status line must be plain markdown, not frontmatter. Consider a `Status: shipped | wip | backlog | abandoned` line directly under the H1. *(Resolved 2026-08-07: added a `Status:` line to all 20 contracts; classification below.)*

#### R6 (LOW) — Duplicate Immich-API knowledge bases
Both `dto-reference.md` (authoritative field/enum/date-format reference) and `.opencode/memory.md` (the "Immich server API gotchas" section) document the same API quirks (ping returns JSON, logout is 200 not 204, PATCH not PUT, columnar bucket DTO, stringified multipart bool, ISO8601 vs `YYYY-MM-DD`). Two sources of truth for the same knowledge is a drift risk; cross-link them and mark one canonical.

## 2. Performance audit

Severity reflects real-world impact on a **large photo library** (the product's target).

### HIGH

#### P1 — Timeline section pipeline recomputed in `body`
`TimelineView.swift:316-318` `timelineSections` is a body-computed property calling `TimelineSectionBuilder.build(from: vm.groupedByDay)`. `vm.groupedByDay` (`TimelineViewModel.swift:162-170`) is itself a computed `Dictionary` build + two sorts (O(n log n)). The entire pipeline re-runs on every state change (selection tick, scroll-to-top visibility, etc.). See R1: the inline comment underestimates this.

#### P2 — `DateFormatter` / `ISO8601DateFormatter` allocated per-call in hot paths
Documented-expensive allocations, one or two **per call**, in four hot paths:
- `TimelineSectionBuilder.swift:52,57` — invoked from `TimelineView` body (P1).
- `PhotoInfoPanel.swift:136,140` — `dateLabel` is a computed property read in body.
- `PhotoViewer.swift:787,791` — `headerDate(for:)` runs per current-asset change.
- `DateHeaderFormatter.swift:69,88,93,98,113,134` — multiple allocations per pinned-day change.

Note: `PhotoInfoPanel.dateLabel` (`:134-145`) and `PhotoViewer.headerDate` (`:785-796`) are byte-for-byte identical — a clear dedup target (one static helper).

#### P3 — `ForEach` with positional ids + per-render array allocation (explore grid)
`SearchView.swift:217` and `:224` use `ForEach(Array(vm.exploreData.enumerated()), id: \.offset)` and `ForEach(Array(section.items.enumerated()), id: \.offset)`. Positional `\.offset` ids prevent correct diffing on reorder/insert (every row rebuilds), and `Array(...enumerated())` allocates a fresh array on every render.

#### P4 — Map photo sheet runs full-array equality on every VM mutation
`MapView.swift:213` `.onChange(of: displayedPhotos)` compares `displayedPhotos` (computed at `:232-234`) by `Equatable` on every VM `visiblePhotos`/`selectedMarkerPhotos` mutation. During a region-filter churn (debounced 250 ms in the VM) this fires array equality over potentially thousands of `MapPhoto` values, and `displayedPhotos` is a fresh array expression on every access.

#### P5 — Full-array `.map` + linear `firstIndex` on every viewer-open tap
`MapView.swift:243-244` `openViewer` maps the entire `displayedPhotos` to `AssetReactItem`s and runs a linear `firstIndex`. Same pattern at `TimelineView.swift:376`, `TrashView.swift:107`, `SearchView.swift:100`, `AlbumDetailView.swift:96`. For the map sheet this can be thousands of items per tap.

### MEDIUM

- **M1** — Fire-and-forget `Task {}` on every cell action (~30 sites across PhotoViewer, Timeline, Trash, Map, Search, Albums). Not stored, not cancelled; outlive the view if dismissed mid-flight and implicitly capture referenced state. Representative: `PhotoViewer.swift:567,590,610,633,644`; `TimelineView.swift:169,194,217`; `TrashView.swift:55,68`; `MapView.swift:81,89,97,133,225`.
- **M2** — Per-region-frame `Task { @MainActor in vm.setVisibleRect(...) }` allocated *before* the VM debounce (`MapView.swift:78-82`). `mapViewDidChangeVisibleRegion` fires continuously, so a new `Task` is allocated per movement frame; the 250 ms debounce lives only in the VM.
- **M3** — Annotation diffing runs in `updateUIView` on **every SwiftUI update** (selection, chrome toggle…), not only on annotation changes (`MapView.swift:330-398`). Bounded (~44² culled set) but unnecessary churn. *(Amplified 2026-08-07: the diff now also builds a `desiredCount: [String: Int]` dictionary plus `toRemove`/`liveMatch`/`toAdd` arrays per update — larger constant factor than the original audit described, still bounded.)*
- **M4** — Six `print(...)` in `MapViewModel.loadMarkers`/`refreshMarkers` (`:205,216,219,224,241,247`) on a `@MainActor` class; string formatting runs even with no console.
- **M5** — `.alert(isPresented: .constant(vm.errorMessage != nil))` no-op binding ×3 (`AlbumsView.swift:53`, `AlbumDetailView.swift:74`, `SharedLinkSheet.swift:53`). The setter is a no-op, so dismissing the alert cannot clear `errorMessage`; can re-present or loop. `TimelineView.swift:179` and `TrashView.swift:46` correctly use `Binding(get:set:)`.
- **M6** — `UIScreen.main.bounds` read in body/hot paths (`PhotoViewer.swift:182`, `PhotoInfoPanel.swift:289`). Deprecated; wrong on iPad split-view / external display / iOS 26 multiscene. PhotoViewer already has a `GeometryReader` `proxy`.
- **M7** — `MapMarkerCache` is an unbounded file cache, single-blob JSON encode/decode of "10k+ markers," no eviction, no size cap (`MapMarkerCache.swift:46-58`). No app-level `UIApplication.didReceiveMemoryWarning` observer anywhere (grep returned nothing).
- **M8** — `DispatchQueue.main.async` / `asyncAfter` for view-state timing (`MapView.swift:57,65,86`; `SharedLinkSheet.swift:114` 2 s timer; `AddToAlbumPickerSheet.swift:76` 0.8 s). Code smell; signals state mutation during a view update.
- **N1 (NEW 2026-08-07)** — Dead-code duplicate `MapViewModel.applyMarkers(_:persist:)` at `MapViewModel.swift:276-284` is never called (the canonical path is `applyMarkers(_:)` at `:256` + `persist(_:)` at `:266-270`). The dead variant contains a **fire-and-forget** `Task.detached(priority: .utility) { cache.save(dtos) }` (unlike the canonical `persist(_:)` which `.value`-awaits the write). No effect today, but a latent footgun if anyone wires it up — either delete it or align it with the awaited pattern.

### LOW

- **L1** — Filmstrip `.id(i)` (positional Int) overrides the stable `ForEach id: \.element.id`; after a delete, identity is recomputed by index, confusing `scrollPosition` (`PhotoViewer.swift:398-419`, scroll at `:427`).
- **L2** — `repeatForever` shimmer launched per placeholder cell on appear (`AuthenticatedAsyncImage.swift:112-117`, `TimelineView.swift:497-502`); cheap individually, multiplies across fast scroll.
- **L3** — `thumbnailURL` allocates `URLComponents` + 2 `URLQueryItem`s per cell render (`AssetThumbnailCell.swift:31` → `ImmichAssetURL.swift:8-18`).
- **L4** — `UISelectionFeedbackGenerator()` instantiated per call instead of prepared/reused (`SearchModeGlassBar.swift:53`).
- **L5** — `shownPhotos = Array(displayedPhotos.prefix(photoLimit))` recomputed per body access (`MapView.swift:237-239`).
- **L6** — `placeName` scans all `visiblePhotos` on every render (`MapView.swift:251-256`).
- **L7** — Single-blob decode of large marker cache (`MapMarkerCache.swift:45-48`). The off-main hop is already in place (`MapViewModel.swift:200-202`); only streaming/chunking is missing.

### Good (preserve)
- `ImageCache` is `NSCache` with `countLimit = 400` / `totalCostLimit = 80 MB`, auto-evicts under pressure (`Services/ImageCache.swift`).
- Every view model uses `@Observable` (Observation tracks only properties read in `body`).
- Map VM debounce is sound: `setVisibleRect` cancels + reschedules a `Task.sleep` (250 ms); `filterVisible` is cooperative-cancelable every 1024 markers; grid subsampling caps annotations at ~44² (`MapViewModel.swift:144,165,301-354`).
- Cache I/O + JSON decode correctly detached (`MapViewModel.swift:200,269,281`).

## 3. Design / HIG audit (iOS 26 / Liquid Glass)

### HIGH

#### D1 — Mixed FR/EN UI copy with no localization discipline
`Resources/Localizable.xcstrings` exists (1357 L, sourceLanguage `en`, partial `fr`) but feature code bypasses it. French literals: `ServerURLScreen.swift:27,33,74,76,78,96,104,126,129`; `LoginScreen.swift:77,88,90`; `WelcomeScreen.swift:29,36,40,60-72`; `MapView.swift:111`; `PhotoViewer.swift:851,924,956`; `ProfileView.swift:20,28,34,37,44`; `SharedLinksView.swift:21`; `SearchModeGlassBar.swift:17-19`. English literals in the same surfaces: `RootView.swift:128,131,183`; `TrashView.swift:47,64,66,75,132,191`; `PhotoViewer.swift:885,924,929`; `AlbumDetailView.swift:106`. Even adjacent screens disagree — `AlbumsView.swift:22` ("No Albums Yet") is English while `ProfileView.swift:20` ("Compte") is French. `MapView.swift:111` ("Chargement des photos…") is French while `:132,186` are English.

#### D2 — `UIScreen.main.bounds` used for layout
Deprecated; breaks on iPad split-view / external display / iOS 26 multiscene. `PhotoViewer.swift:182` (info-panel geometry) and `PhotoInfoPanel.swift:289` (EXIF grid columns). A `GeometryReader` `proxy` is already in scope at `PhotoViewer.swift:177` but is deliberately avoided per the comment at `:178-181` (a `fullScreenCover` inset workaround). (Cross-listed as M6.)

#### D3 — A `View` lives inside `UploadViewModel.swift`
`UploadViewModel.swift:55-92` defines `BackupSettingsView` (a `Form` in a `NavigationStack`). Anyone doing IA/design work by filename will miss it. Move it next to the other views or rename the file.

#### D4 — `.font(.pvCaption)` used for Form body copy
`UploadViewModel.swift:70` uses `pvCaption` (13 pt) for explanatory body text inside a `Form`, while every other descriptive body in the app uses `pvBody`/`pvSubhead`. Inconsistent type role for the same informational content.

### MEDIUM

- **D5** — `Color.gray.opacity(0.12)` hardcoded card background on `InfoCard` (used by ≥5 EXIF cards). Won't adapt with the brand system the way `bgSecondary`/`bgTertiary` do; flat system gray clashes with the Immich indigo-tinted neutrals (`PhotoInfoPanel.swift:269`).
- **D6** — `.font(.system(size: 16, weight: .semibold))` for the search-mode glyph bypasses the exact-match token `pvBodyLarge` (`SearchView.swift:116`).
- **D7** — `.buttonStyle(.borderedProminent).tint(.red)` on the editor "Revenir à l'original" reset — the only `.borderedProminent` in the app and the only hardcoded `.red` tint. The comment says `DS-exempt: destructive CTA`, but `Color.immichError` exists precisely for this. Every other destructive action uses `PVPrimaryButtonStyle` + `Button(role: .destructive)` (`PhotoEditorView.swift:54-55`).
- **D8** — No `GlassEffectContainer` despite ~13 `glassEffect` sites. iOS 26 guidance: wrap sibling glass controls in a container so they morph/merge. The PhotoViewer top bar (`:339` back + `:360` location capsule + `:371` info) and bottom bar (`:448,495,511`) are tight stacks of independent glass bubbles that will render separately instead of as unified chrome. Other sites: `SearchView.swift:119`, `SearchModeGlassBar.swift:51`, `PhotoInfoPanel.swift:88`.
- **D9** — `immichBottomBar()` forces `.toolbarBackground(Color.bgSecondary, .visible, for: .tabBar)` (`ImmichAppBar.swift:56-63`) + `.tabBarMinimizeBehavior(.never)` (`RootView.swift:95`). This is a documented, intentional brand choice (`:51-54`), but it opts the whole app out of the iOS 26 floating-glass tab bar. Flag for review.
- **D10** — `immichPrimary` defined in **two** sources of truth with identical RGB: code (`ImmichColors.swift:13-16`, dynamic light/dark) **and** asset catalog (`AccentColor.colorset` + `BrandIndigo.colorset`, referenced by string in `Color+PhotoVault.swift:37-43`). Drift risk.
- **D11** — Soft-deprecated color aliases still used in 10 feature files. `Color+PhotoVault.swift:22-34` marks `brandIndigo`, `brandIndigoMuted`, `statusSuccess`, `statusPending`, `statusError`, `accentInfo` as deprecated (`use Color.immich*`). Still in use: `AssetThumbnailCell.swift:159,176` (`accentInfo`); `TimelineView.swift:135` (`accentInfo`); `MapView.swift:161` (`brandIndigo`); `ImmichAppBar.swift:43,59` (`brandIndigo`); `PVButtonStyle.swift:15` (`brandIndigo`); ~15 usages total. Migration incomplete.
- **D12** — `Color.white` hardcoded for glass-chrome labels throughout the PhotoViewer (`:337,350,355,369,446,464,486,509`). Apple recommends the system primary so glass adapts; white assumes "always over a dark photo" (the viewer background is forced black at `:186`). Brittle if a light photo ever sits behind a glass control.

### LOW
- **D-L1** — Magic numbers off the spacing scale (most are commented `DS-exempt` per spec §8.6, but `PhotoEditorView.swift:154,185,188` fixed-width label columns won't reflow under Dynamic Type, and `PhotoViewer.swift:141,146,433,769` chrome-height math is load-bearing).
- **D-L2** — Sub-44pt tap targets: `SearchView.swift:118` mode-menu button 30×30; `PhotoInfoPanel.swift:87` close 40×40; `PhotoViewer.swift:338,370,447,510,843,862` various 40×40. Glass circles are visually OK but technically below HIG minimum.
- **D-L3** — `.alert(isPresented: .constant(...))` ×3 — cross-listed as M5.
- **D-L4** — `UISelectionFeedbackGenerator().selectionChanged()` in one file vs `.sensoryFeedback` everywhere else (`SearchModeGlassBar.swift:54`); also a perf micro-issue (L4).
- **D-L5** — No `.accessibilityHint` anywhere in the codebase. Labels are descriptive, so low priority.
- **D-L6** — Inconsistent toolbar placement vocabulary: `.navigationBarTrailing` (`SearchView.swift:54`) vs `.topBarTrailing` (`TrashView.swift:231,242`; `AlbumsView.swift:34`; `AlbumDetailView.swift:39`; `TimelineView.swift:394`). Both work; `.topBar*` is canonical.
- **D-L7** — Dead colorsets: `Resources/Assets.xcassets/Logo{Green,Yellow,RedPink,Blue}.colorset` have full light/dark values but no `Color("Logo…")` references in `Sources/`. Staged for an unbundled multi-color logo per `ImmichAppBar.swift:8-12`.

### Good (preserve)
- Centralized design system: `Sources/DesignSystem/Tokens/{Color,Spacing,Font,Motion,Shadow}+PhotoVault.swift` + 10 components. 4 pt grid (`PVSpacing`), radius scale (`PVRadius`), motion tokens with `reduceMotion` adaptive fallback (`Motion+PhotoVault.swift:21-23`).
- Dynamic light/dark via `Color(light:dark:)` → `UIColor(dynamicProvider:)` (`ImmichColors.swift:63-67`).
- Native patterns preferred: `Form`, `List`, `ContentUnavailableView`, `.searchable` + `.searchSuggestions`, `NavigationStack(path:)` for onboarding.
- iOS 26 `Tab(role: .search)` for the search bubble (`RootView.swift:90`) — uses the system Liquid Glass search presentation, not a custom FAB.
- PhotoViewer glass: 8 `.glassEffect(.regular, in:)` controls, glass location capsule, glass bottom bar, native aspect-ratio filmstrip, swipe-up EXIF panel with `PhotoViewerSwipeDecision` thresholds, `.simultaneousGesture` so zoom/pan never fight chrome, layout space reserved via `safeAreaInset`.
- Reduce Motion honored via `@Environment(\.accessibilityReduceMotion)` + `PVMotion.adaptive` (`RootView.swift:18,60`; `TimelineView.swift:17`; `PhotoViewer.swift:149`).
- `.sensoryFeedback` used pervasively and semantically (success/warning/error/selection/impact).
- Accessibility grouping on composite cells (`.accessibilityElement(children: .combine)`), headers use `.isHeader`, decorative placeholders `.accessibilityHidden(true)`.
- `.symbolEffect(.bounce)` + `.contentTransition(.symbolEffect(.replace))` for the selection checkmark (`AssetThumbnailCell.swift:174-175`).
- `scrollTransition` parallax correctly scoped to thumbnail content with an explicit FM-3 mitigation comment (`AssetThumbnailCell.swift:39-45`).
- Onboarding flow is textbook: one screen per file, `NavigationStack(path:)`, `PVHeaderBadge` hero, `PVInputGroup` cards, `.submitLabel` chains, in-context `InlineErrorBadge` (never popups), CTA pinned via `safeAreaInset` over `.regularMaterial`.

## 4. Per-screen notes (red flags)

- **RootView** — 5-tab `TabView` (Photos/Albums/Shared/Me + Search `role: .search`). `.immichBottomBar()` forces an opaque gray tab bar (D9). Search-bubble icon swap logic (`:141-158`) changes the bubble's action per tab — discoverability concern. Map photo sheet uses detents + `.presentationBackground(.regularMaterial)` (good).
- **SearchView** — 3-mode switch under a floating glass `SearchModeGlassBar` pinned via `safeAreaInset(.top)`. Hardcoded font `:116` (D6), 30 pt tap target `:118` (D-L2), positional `ForEach` ids `:217,224` (P3), mixed FR/EN (D1).
- **MapView** — `ClusteredMapView` (UIViewRepresentable MKMapView with real `clusteringIdentifier`) ignores safe area; centered loading capsule (`.regularMaterial` + `Capsule`). Cluster markers tinted `.systemIndigo` (`:418,437`) — UIKit-level, not DS `immichPrimary` (brand drift). `.systemIndigo` + "Chargement des photos…" (FR) vs surrounding EN (D1).
- **SearchModeGlassBar** — Custom 44 pt glass segmented control with sliding highlight (justified in `:7-11`: native picker can't do icon+label + instant snap).
